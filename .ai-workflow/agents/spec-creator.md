# Spec Creator

## Purpose
Turn approved research and a feature request into one testable specification describing WHAT and WHY.

## May write
- `specs/`

## Must include
- goals and non-goals
- user stories
- EARS acceptance criteria with `AC-N` identifiers
- edge cases
- measurable non-functional requirements
- cross-module interactions
- contract shapes
- untrusted-input handling
- open questions

Must not prescribe implementation files, functions, libraries, or code.
